# Interface localization

Preshot supports Simplified Chinese (`zh`, default) and English (`en`). Choose
either language in the top-right Settings dialog. Changes apply immediately;
desktop preferences are persisted in `%USERPROFILE%\.preshot\settings.json`.
Unsupported or missing preferences recover to Chinese. The browser test adapter
keeps settings only for its injected repository lifetime.

## Ownership and runtime

- `domain/settings/models.ts` defines and normalizes the language preference.
  Domain models remain pure and do not import i18next, React or browser globals.
- `app/theme/ThemeProvider.tsx` owns the existing settings repository and publishes
  language preferences through `app/language/LanguageContext.ts`. Settings writes
  are serialized patches, so theme, panel-width and language changes cannot
  overwrite one another. Failed writes remain visible and can be retried.
- `shared/i18n/config.ts` bundles both languages offline. It uses the existing
  semantic `translation` namespace and an explicit source-copy `ui` namespace.
  `locales/en.ts` must match the structure of `locales/zh.ts`.
- `locales/ui.en.json` contains the English translations of application-owned
  Chinese source messages. Those source keys are also the Chinese resource.
  `ui(source, values)` looks up the entire key with namespace/key separators
  disabled. Interpolated names, text, paths and identifiers are never translated.
- React views subscribe with `useTranslation` or `useUiLanguage`. Do not key a
  workspace, editor or draft by language. Existing project sessions, media,
  selection and undo/redo history must survive a switch.
- BlockNote 0.53 fixes its dictionary reference when constructing an editor.
  `editorLanguage.ts` supplies dictionary getters and scoped placeholder CSS to
  update menus and empty-block hints without recreating that editor. The original
  upstream dictionaries are never mutated.
- The HTML language and UI date formatting follow the preference. Export field
  labels and metadata use the selected language; PDF, DOCX and long-image export
  retain their independent existing rendering and saving pipelines.

## Coverage inventory

| Area | Treatment |
| --- | --- |
| Shell and workspace | Project actions, focus mode, launcher, parent-folder picker, loading stages, save/discard/cancel and settings are localized. |
| BlockNote and components | Upstream menus/placeholders, custom slash menu, block actions, artifact fields, image groups and resize descriptions are localized. Chinese and English search aliases remain available together. |
| Image operations | Upload/embed/screenshot controls, crop/lightbox, clipboard feedback and drag keyboard/live-region instructions are localized. Native capture windows follow the operating system language. |
| Material library | Search, categories, cards, details, preview, metadata editor, creation, insertion modes, duplicate checks, recycle bin and recovery guidance are localized. |
| Export | Presets, formats, progress, limits, cancellation and generated fixed field labels are localized. Document content is retained verbatim. |
| Accessibility | Accessible names, tooltips, placeholders, dialog names and announcements use the same resources as visible copy. Language options retain their native names. |
| Static label tables | Store source labels and translate at consumption, or expose getters. Do not evaluate translated labels once at module initialization. |
| User data and compatibility | Project/material names, descriptions, tags, captions, document text, filenames, stored templates and legacy migration inputs are data; a language change must never rewrite them. |
| Domain/native diagnostics | Existing error codes and diagnostic bodies remain stable. Adapter context and known recovery instructions are localized. Unknown diagnostic details remain verbatim instead of being guessed or discarded. |
| Cached images | Existing thumbnails and screenshots are image content. Language changes do not regenerate every cached image or load full previews. New captures use the current render language. |

## Rules for future changes

1. Prefer semantic keys for new product concepts. The source-copy namespace is
   retained for the migrated UI and must not be used to translate arbitrary data.
2. Translate whole sentences. Use named interpolation values instead of joining
   translated fragments; use i18next plural forms when wording depends on count.
   Keep units, keyboard shortcuts and technical identifiers explicit.
3. New domain/native failures should expose stable codes and structured values.
   Map them to localized messages at the presentation/adapter boundary, preserving
   the original diagnostic as a cause. Do not classify business behavior by the
   localized message or send the renderer language into domain logic.
4. New persistent starter/template content needs an explicit creation-time locale.
   Generate it once; reopening or switching language must preserve later edits.
   Existing Chinese starter projects and imported templates remain unchanged.
5. If thumbnail language becomes a product choice, version its render-key/cache
   contract first. Do not invalidate original assets or trigger bulk preview
   generation merely because the interface language changed.
6. Keep native OS dialogs in the OS language. Application-supplied dialog titles
   belong in the resources; Windows screenshot UI and installer localization are
   separate platform work, not renderer string replacement.

## Follow-up migration plan

The remaining domain/native diagnostic bodies should be migrated by error-code
family, starting with clipboard decode/access failures, then material recovery,
then workspace/media validation. Each family needs code-to-message coverage in
both languages, argument preservation and unknown-code fallback tests. Preserve
existing receipt hashes, serialized payloads and native command compatibility.

Replace the remaining inherited sentence fragments with complete semantic keys
when changing those flows, covering count/plural, punctuation and word order.
Audit new model defaults and templates at their creation boundary, not while
rendering stored documents. Localization of old user-owned starter content,
existing raster thumbnails and third-party diagnostic prose is deliberately not
automatic.

## Validation

Run `pnpm i18n:check`, or `pnpm i18n:check -- --inventory` for the remaining
non-call literal counts by source area. This check validates semantic catalog
parity, English values, interpolation parity, registered source keys and the
absence of hard-coded Chinese JSX text/attributes. Non-call counts include
intentional data, aliases and catalog-backed static label tables; they are not
an untranslated-UI count.

Settings tests cover persistence, rapid switches interleaved with theme writes,
and persistence failure/retry. The real BlockNote regression checks unchanged
editor identity, document text, change events and undo history. The browser smoke
test `e2e/language.spec.ts` traverses settings, shell, material preview and export
in English, then switches back to Chinese while preserving Chinese user content.
Tests use disposable repository data and never read the live image clipboard.
