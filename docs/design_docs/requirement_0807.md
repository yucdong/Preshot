- The final empty slot in an image group is normally blank, but when the pointer moves over it, show vertically stacked Insert and Capture buttons there. The user can click them to insert an image at that position.
- Change the Capture button to a scissors icon.
- If the front part of an image group has no images and the remaining images have been pushed to the next page, move the entire frame directly to the next page and leave the remaining space on the previous page blank.
- When the pointer hovers any of the four edges of a component, show a bidirectional arrow so the component can be resized.
- Implement an auto-layout algorithm. By changing component sizes and positions (ordered top-to-bottom, then left-to-right), components can share the same row when their widths are small enough, and layout should be recalculated to fill the page.
- Component names can be edited, but the component-name text box should not occupy the entire top bar. It should match only the text width, and the remaining area should stay part of the card border. Clicking the card border should drag the card. In addition to the top edge, the left, right, and bottom edges should also have card borders with the same width, and all of them should support dragging.
- Reference image components should include a default description text box whose initial text is "Reference image notes". On the right, show a "Hide" checkbox that controls whether the text is displayed and affects PDF export.
- By default, images in an image group should not show captions. Each image decides independently whether it has descriptive text. When the pointer hovers over an image, also show a caption box that can be edited. After editing, display the text below the image. Reduce the image height to make room for the text, using at most one third of the height for captions. If the text is too long, reduce the font size, with a minimum font size of 5. If it still does not fit, automatically adjust the overall image-group size (height).
- Can screenshot support be implemented with a native JavaScript library? Invoking the Windows native snipping tool seems relatively heavy.
- For image size, show the current height in pixels so multiple image groups can be configured consistently.
- For images inside an image group, when the pointer hovers around an image edge, dragging should resize the image and then scale it to the height of that image group while preserving its aspect ratio. Persist resized images. On hover, show a bottom-left button that restores the original image size when clicked.
