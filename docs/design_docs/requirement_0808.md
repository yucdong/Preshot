# A4 文档流画布

## 原始需求

- 画布严格按照可打印 A4 纸尺寸设计，屏幕与 PDF 所见即所得。
- 所有组件独占一行，同一行不允许放置多个组件。拖动组件用于调整顺序。
- 单个组件不允许跨页；当前页放不下时，组件整体移动到下一页。
- 图片组先缩小图片，达到最小尺寸后仍放不下时，在下一页创建续页图片组，名称增加 `(2)`、`(3)` 等后缀。
- 文案不缩小字号，内容放不下时按 BlockNote 块拆分到下一页的新文案组件。

## 2026-08-08 澄清结论

- 组件保留宽度和高度调整能力，但无论多窄都独占一整行，剩余横向空间不能放入其他组件。
- 自动创建的续页图片组和文案是项目中的真实组件：写入 `.preshotproj`，可独立编辑、拖动、撤销和重做。
- 图片自动缩放的最小高度为 `67.5pt`，约等于屏幕 `90px`（96 DPI）；图片保持各自当前宽高比。
- 默认仍遵守 `67.5pt` 图片下限；用户明确选择“强制单页”时，允许对指定图片组统一缩小到该下限以下，并持久化实际 frame 尺寸。
- 文案优先在 BlockNote 顶层块边界拆分；单个超过整页的块允许在块内部按可见行拆分，避免无法排版。
- 文案卡片高度双向适配实际 BlockNote 内容：增加文本、列表编号或换行时增长，删除内容时收缩；历史保存高度不能阻止收缩。
- 图片组卡片高度双向适配标题、介绍控件和最终图片行底部：图片增加/放大时边框下移，图片删除/缩小时边框上移，不保留历史空白高度。
- 文案编辑器内部不插入跨页空白。超过一页时只通过持久化 `(2)`、`(3)` 续页组件分页。
- 用户明确选择“强制单页”时，文案组件可持久化 `contentScale`（范围 `0.5–2`）；屏幕与 PDF 使用同一比例，其他未设置组件仍为 1。
- 旧项目迁移后按原组件 `y`、再按 `x` 排序一次；之后数组顺序是唯一的纵向顺序来源。
- schema v7 是连续自由画布，历史组件高度允许超过一页；迁移校验不能提前套用 v8 的单页限制。v7→v8 时先将临时高度限制到 A4 内容高度，再由图片/文案归一化创建续页组件。

## 验收标准

- 屏幕显示独立 A4 纸张、页边距和页间距；组件内容不进入不可打印边距。
- 任意两个组件不能处于同一视觉行，组件之间使用统一纵向间距。
- 高度不超过一页的组件永远不会跨页；当前页不足时整体出现在下一页顶部。
- 拖动组件只改变数组顺序，不再保存自由纵向坐标。
- 自动拆分是一条结构历史记录；撤销恢复拆分前组件，重做恢复续页组件。
- 单页内的短文案卡片底部只保留组件内边距，不因其所在页面位置产生额外空白。
- 有序列表编号变化造成的换行会触发 DOM 重新测量并同步卡片高度。
- 图片组边框底部只保留组件内边距；两个收缩后的连续组件高度与行间距之和小于 A4 可打印高度时，必须排在同一页。
- PDF 使用与屏幕相同的页尺寸、边距、组件顺序、拆分结果和图片尺寸。
- 包含超高组件的合法 schema v7 项目可以加载并迁移到 v8；schema v8 和未来版本仍执行严格字段与边界校验。
